# Electrodynamics knowledge-base maintenance

## Source authority and scope

Use the user's explicit instructions and supplied course lectures, homework and syllabus as the authority for course coverage and unit conventions. Use study conversations to preserve the learning path. Check [[Sources/Course Sources]] before relying on source labels, page numbers or a questionable statement. Do not guess lecture numbers, homework content, due dates or student progress.

Use Gaussian units with explicit $c$ unless the course task explicitly asks for a comparison. Distinguish microscopic/vacuum expressions from macroscopic material formulas. If a source has an apparent sign error or missing assumption, record the exact source location and a narrow explanation rather than silently repeating or replacing it.

Start with existing discussed topics. Do not expand [[Green functions]] or other future topics merely because they appear in the uploaded full-course notes. Assignment maps may name needed but unstudied tools as gaps.

## Inspect before editing

1. Read the repository tree and local instructions. Search filenames, aliases, wikilinks and content for the concept, including synonymous wording and symbols.
2. Read an equivalent note in full and update it instead of creating a duplicate.
3. Preserve useful examples, questions and corrections. Do not replace durable conceptual notes with transcripts.
4. Show proposed paths, renames, removals and rationale before any large restructuring. Ordinary scoped additions or corrections already authorized by the user may proceed.
5. After edits, check internal links and source references. Inspect the diff before committing; preserve unrelated work and never force-push.

## Concept-note structure

Every important concept note uses these headings: One-sentence meaning; Prerequisites; Core equations; Where they come from; Assumptions; Physical meaning; When to use it; Example; Common confusion; Related concepts; Used in.

Write clear English from fundamentals upward. Link prerequisites and relevant course/homework locations with Obsidian wikilinks. Keep derivations at the studied level; mark missing source links honestly. Label actual earlier misconceptions accurately; generic teaching examples must not be invented as user memories.

## Homework maps

Map each problem to verified lecture sections and prerequisite concepts. Record the system, knowns/unknowns, symmetry, assumptions, governing equations and an understanding/status checklist. Do not copy instructor solutions or construct full worked solutions inside a map. Do not mark submission, self-grading or mastery complete without evidence. Preserve explicit assignment-version ambiguities.

## Guided study behavior

First explain the lecture's physical problem, prerequisites and main results. Teach one section at a time; explain each important equation's origin, assumptions, meaning and use. Pause with one or two short questions. For homework, map the problem first; let the user choose and attempt steps with progressive hints. Do not jump to a complete derivation or solution before checking understanding.

## Format and maintenance

All vault content is plain Markdown. Use Obsidian wikilinks internally and Markdown math. Maintain [[00 Course Map]] and the relevant homework map whenever conceptual dependencies or understanding status changes. Intentionally unresolved future links must be identified as such; initially only [[Green functions]] is allowed.

Changes are made in authorized sessions; no unattended monitoring or automatic synchronization is configured. Keep only course-relevant learning context in this repository.
